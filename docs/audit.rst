実装監査記録
============

共通方針
--------

全実装について、要素数・頂点数0/1、空区間、重複操作、複数回呼び出し、
内部状態の公開、再帰上限、docstringと計算量を確認しました。ランダムテストは固定
seedとnaive実装を使います。テストは ``tests/`` にあり、外部グラフライブラリや
property-based testingライブラリには依存しません。

UnionFind
---------

**発見事項:** ``myUnionFind`` が命名規約外、``n`` が要素数でなく成分数へ変化し、
``get_self_size`` が内部配列そのものを返していました。再帰findも不要でした。

**修正:** ``UnionFind``、``group_count``、``size(x)``、反復findを導入し、内部配列を
返す旧APIは削除しました。空集合、自己union、既連結union、成分サイズと全組の連結性を
naiveラベル管理と比較しました。動的な辺削除は現在も非対応です。

WeightedUnionFind
-----------------

**発見事項:** 内部配列が公開され、再帰findでした。矛盾時の ``False`` という仕様が
docstring以外で明確でなく、``same`` と成分サイズ取得がありませんでした。

**修正:** 内部状態を非公開化し、反復経路圧縮へ変更。整合制約、未連結、自己制約、
矛盾制約が状態を変えないことを、重み付き無向グラフのBFSポテンシャルと全頂点対で
比較しました。加法で表せない制約と削除には非対応です。

SuccessorDSU
------------

**発見したバグ:** 昇順に全要素を削除後 ``next(0)`` を呼ぶと、親鎖が長くなり
``RecursionError`` になり得ました。範囲検査と重複削除の戻り値もありませんでした。

**修正:** findを反復化し、``erase`` は初回だけ ``True``、``next`` は見つからない
場合 ``n`` と定義。長さ5000の鎖と、生存配列の線形探索とのランダム比較を追加。
削除の取り消しとpredecessor queryは非対応です。

FenwickTree
-----------

**発見事項:** クラス名が ``Fenwick_Tree``、内部配列が公開、境界探索の説明が
「prefix endpoint」と「要素index」を混同していました。

**修正:** 0-indexed要素位置として、``lower_bound(target)`` は累積和がtarget以上、
``upper_bound(target)`` はtarget超となる最初の位置、存在しなければ ``n`` と明記。
長さ0、先頭・末尾、0要素を含む配列と全探索を比較しました。負要素を含む場合の境界
探索は非対応です（区間和自体は利用可能）。

SegTree
-------

**発見事項:** 実装ロジックに再現可能なバグはありませんでしたが、ファイル名と長大な
モジュール説明を整理しました。

**検証:** 空区間・長さ0/1、1点更新、非可換な文字列連結、ランダム区間和、
``max_right`` / ``min_left`` をスライス全探索と比較しました。演算の結合則、単位元、
述語の単調性は呼び出し側の前提です。

LazySegTree
-----------

**発見したAPI問題:** 旧 ``apply(left, right=None, f=None)`` は ``f is not None`` を
要求し、自然な ``apply(index, action)`` を区間呼び出しと誤認しました。また作用に
``None`` を使えませんでした。

**修正:** 1点の位置引数・キーワード形式と3引数の区間形式を分離する番兵を導入。
一次関数作用で非可換なcomposition順、空更新、1点更新、区間和、境界探索をnaive配列
と比較しました。モノイド作用の法則自体は呼び出し側の前提です。

SCCGraph
--------

**発見した問題:** 再帰Tarjan実装がプロセス全体の再帰上限を変更し、深いグラフでは
Python/Cスタックに依存しました。辺端点の検査もありませんでした。

**修正:** 反復Kosaraju法へ変更。空グラフ、自己ループ、多重辺、長さ3000のパス、
複数回呼び出しを確認し、小規模グラフではFloyd-Warshallの相互到達可能性と比較。
成分間の全辺でIDがトポロジカル順になること、縮約辺の重複除去と入次数も検証。
動的SCCは非対応です。

MFGraph
-------

**発見事項:** ``src/dst/cap`` と他グラフAPIの命名が不統一で、負の ``flow_limit``、
``min_cut`` の始点、容量の整数性に検査がありませんでした。

**修正:** 正規名を ``from_vertex/to_vertex/capacity`` とし旧Edge属性propertyを維持。
自己ループ、多重辺、容量0、辺変更、呼び出し回数とflow limitを検証。頂点2〜7の
ランダムグラフで全カット列挙の最小値と最大流を比較し、最大流後の到達集合が作る
カット容量も照合しました。費用・下限・浮動小数容量は非対応。``change_edge`` 後の
流量保存則は利用者責任です。

FlowLowerBound
--------------

**監査対象:** 添付された、下限分を事前に流して超始点・超終点と人工辺 ``t -> s``
による実行可能循環へ帰着する実装を確認しました。

**確認・修正:** balanceの符号、人工辺が保持する初期フロー、補助辺を逆残余辺ごと
無効化してから追加最大流を求める順序を確認しました。実行可能循環を構築する
``circulation`` と、0以上の ``source`` 正味流出量を最大化する ``flow`` を同じ
クラスにまとめました。両者は排他的に1回だけ呼べます。正規APIの入力検査、辺
スナップショット、計算量、自己ループ・多重辺対応を追加。

**追加テスト:** 頂点2〜5、辺数0〜6、上下限0〜2の固定seedランダムグラフ400件で、
全辺流量の直積を列挙するnaive解と最大値を比較しました。返却フローについて上下限、
全内部頂点の流量保存則、始点・終点の正味流量も再検証。容量0、固定流量、自己ループ、
多重辺、実行不能、実行可能な最大値0、呼び出し順と1回限定も個別に確認しました。
循環流についても頂点1〜5の固定seedランダムグラフ500件を全列挙と比較し、全頂点の
流量保存則を再検証しました。空グラフ、固定循環、実行不能、両モードの排他性も確認。

**現在の制約:** 費用・負容量・浮動小数容量・頂点需要・動的な辺追加には非対応。
実行不能後は最終辺流量を取得できず、最小カットAPIは提供しません。

Trie
----

**発見事項:** 根とノードの可変辞書を公開し、辞書順列挙が再帰深さに依存しました。
重複insertの成否も返しませんでした。

**修正:** ノードを内部化し、反復列挙、集合サイズ、操作成否を追加。空文字、prefixと
単語の区別、重複insert、存在しないdelete、長さ3000の語を確認し、固定seedで
Python ``set`` と全操作・辞書順列挙を比較しました。削除ノードの物理回収はしません。

RollingHash
-----------

**発見したバグ:** 文字を ``ord(char)`` のまま使ったため、先頭NUL文字の寄与が0に
なり、``"\\0a"`` と ``"a"`` のような長さ違いで決定的に同じハッシュ値になりました。
また異なるインスタンスの比較時に長さ確認を利用者へ委ねていました。

**修正:** 文字値を ``ord(char) + 1`` とし、長さとハッシュを比較する ``same`` を追加。
空区間、NUL、異なるインスタンス、ランダムな全長・区間を実部分文字列と比較しました。
確率的衝突は仕様上残り、基数はプロセス間で安定しません。

未解決事項
----------

テストは広い小規模入力と明確な不変条件を対象にしていますが、形式証明ではありません。
Rolling Hashの確率的衝突、コールバックで可変オブジェクトを破壊した場合、Pythonの
旧APIからの自動移行までは保証しません。正規実装は入力範囲を例外で検査します。
